== Introduction

=== Purpose

A whole-slide image is given facts when its slide is scanned that never
change afterwards: the laboratory's identifier for the slide, its stain, the
date and time of the scan, and the identity of the scanner. I2S is the
vocabulary for those facts. It names each one as a key with a value type, a
multiplicity, its DICOM counterpart where DICOM has one, and an identity class
stating whether its value can identify a person.

I2S is published as a machine-readable schema, `spec/i2s_header.json` and
`spec/i2s_keys.json`. A generator compiles it into a C++20 header,
`I2S_Keys.hpp`, and into the tables and key sections of this document, so
neither can disagree with the schema. Implementers *should* consume the schema
or the generated header rather than transcribe this document. The schema and
the generator are at {repository}.

=== Conventions

The key words *shall*, *shall not*, *should* and *may* are normative. A
*reader* is software that reads I2S attributes from a file; a *de-identifier*
is software that removes or replaces what can identify a person before a file
is shared.

== Scope and Identity

=== Slide facts and clinical metadata

I2S covers facts of the slide fixed when it was scanned. It does not cover
the patient. In an Iris File Extension (IFE) file, attributes marked
`METADATA_I2S` hold I2S keys, and every pair promises to identify no
individual; clinical and identifying information is carried in the clinical
metadata stream (HL7 v2 or FHIR) instead. A slide is then de-identified by
dropping that stream, together with the handling of the I2S keys below whose
identity class or PHI flag requires it.

I2S follows DICOM keywords where DICOM has the fact, and diverges where it
does not or where DICOM's attribute means something else. A divergence is
stated in the key's section.

=== Identity classes

Every key has one identity class. A key whose value is found to identify a
person leaves I2S: it is deprecated and its fact moves to the clinical
metadata stream.

include::{generated}/identity_classes.adoc[]

A de-identifier *shall* treat the value of an `UNDER_REVIEW` key as
identifying, unless the key's PHI flag states for the file that it is not.

=== The Digital Image Identifier and its PHI flag

`DigitalImageIdentifier` (short name `DII`) is the identifier the laboratory
gave the slide when it was accessioned. It has no DICOM keyword: DICOM's
Accession Number identifies an imaging service request, and its Container
Identifier identifies the slide container.

Whether an accession-derived identifier identifies a person depends on the
laboratory. I2S therefore carries the answer per file, in the BOOLEAN key
`DigitalImageIdentifierIsPHI` (short name `DII_is_PHI`):

* `true`: the DII is protected health information, and a de-identifier *shall*
  scramble it.
* `false`: the DII identifies no individual, and a de-identifier *may* keep it.
* Absent, while the DII is present: a reader and a de-identifier *shall* treat
  the DII as protected health information and scramble it. This is the safe
  default; a writer that knows the DII identifies no one *should* write the
  flag as `false`.

The flag is a fact about the DII and identifies no one itself.

== Value Types

A key's value is written as text. Each value type defines the text's lexical
form; the example beside each is checked against that form whenever the
specification is validated.

include::{generated}/value_types.adoc[]

A `DATE_TIME` *shall* carry a UTC offset. Its precision is the second, with an
optional fraction to the microsecond, and its range is 0001-01-01 to
9999-12-31.

A key with multiplicity `1-n` holds one or more values; `n` means no upper
bound.

== Versioning and Change

=== Append-only

I2S is append-only. Once a version is published, no key, value type or
identity class is removed, renamed, retyped or remapped, and no key's short
name, DICOM counterpart, multiplicity or PHI flag changes. A key is retired by
marking it deprecated, with the reason; it stays defined so that files
written with it can still be read, and a deprecated key is never restored.
The one fact that may change is the identity class of an `UNDER_REVIEW` key,
which exists to be decided.

These rules are checked mechanically. The generator compares the
specification with a committed record of every published fact and refuses any
change it forbids, naming the key and both values.

=== Adding a key

. Add the key to the newest version's group in `spec/i2s_keys.json`; a key is
  never added to an older version, nor to a ratified one.
. Map it to DICOM where DICOM has the fact, checked against the current
  standard, with the source's URL and the date it was read.
. Validate and canonicalize the files with `python3 -m generator --fix`.
. Record the addition in the committed record of facts with
  `python3 -m generator --refresh-witness`, in the same change.

=== Versions

Every version group of the schema is a revision in the revision history. The
specification's version is the newest revision; revisions follow one another
without a gap (the next minor version, or the next major version at minor 0),
and only the newest may be a draft.
